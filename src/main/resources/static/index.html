1. Spring Security & JWT

  • Passwords: Stored hashed with BCryptPasswordEncoder — never stored in plain text.
  • Stateless Sessions: No server-side HTTP session; each API request carries a cryptographic token in Authorization: Bearer <token>.
  • Ownership Verification: Before deleting or updating any transaction/budget, the service confirms transaction.getUser().getId().equals(user.getId()).

2. Why BigDecimal for Money?

  • Never use double or float for money: Floating-point binary representation creates rounding errors (e.g., 0.1 + 0.2 = 0.30000000000000004).
  • BigDecimal: Provides arbitrary-precision fixed-point arithmetic stored in PostgreSQL as numeric(19, 2).

3. Real-Time Budget Tracking

  • The spent amount is not hardcoded. Whenever budgets are fetched, the service runs a SQL sum query:
  • SELECT COALESCE(SUM(amount), 0) FROM transactions WHERE type='EXPENSE' AND category=:cat AND month=:m
  • remaining = monthlyLimit - spent

4. Global Exception Handler

  • Uses @RestControllerAdvice to catch application errors globally.
  • Translates domain errors into clean HTTP codes: 404 (Not Found), 409 (Conflict/Duplicate email), 400 (Validation failed).

🗄️ Database Tables (Entity-Relationship)

users
• id (PK, BigInt)
• name (VarChar)
• email (Unique VarChar)
• password_hash (VarChar)
• created_at (Timestamp)
transactions
• id (PK, BigInt)
• amount (Numeric 19,2)
• type (INCOME / EXPENSE)
• category (VarChar)
• transaction_date (Date)
• user_id (FK → users.id)
budgets
• id (PK, BigInt)
• category (VarChar)
• monthly_limit (Numeric 19,2)
• budget_month (YYYY-MM)
• user_id (FK → users.id)
